# 🐍 [2026-01] 나만의 파이썬 소프트웨어 개발 프로젝트

## 1. 시나리오 제목
스마트 수질 관리 및 공정 효율 분석 시스템 (Water Quality Monitoring & Efficiency Analysis System)
<br>


## 2. 시나리오 (5~10줄)
이 프로그램은 환경시스템공학 전공 지식을 활용하여, 수처리 시설의 오염물질 제거 성능을 분석하고 관리하는 '전공 특화형 관리 시스템'입니다. 
사용자는 특정 지점의 유입수와 유출수의 오염 농도(BOD, COD 등)를 입력합니다. 
시스템은 이를 바탕으로 오염물질 제거 효율을 계산하고, 법적 방류수 수질 기준과 비교하여 적합 여부(Pass/Fail)를 판별합니다. 
또한, 특정 기준치를 초과할 경우 경고 메시지를 출력하여 공정 개선이 필요함을 알리는 로직을 포함합니다. 
최종적으로는 메뉴 시스템을 통해 여러 측정 지점의 데이터를 통합 관리하고, 전체 공정의 평균 효율을 조회하거나 파일로 저장할 수 있도록 시스템을 확장하여 완성할 계획입니다. 

<br>


## 3. 예상 기능 및 메뉴 (최소 5개)
1단계: 수질 데이터 입력: 측정 지점명 및 유입/유출 농도 입력 
2단계: 제거 효율 계산: 유입 대비 제거된 오염물질 비율(%) 산출 
3단계: 방류 적합성 판별: 법적 기준치와 비교하여 등급 산정
4단계: 공정 개선 알림: 기준 초과 시 효율 개선 보상/경고 로직 실행 
5단계: 전체 모니터링 리포트: 관리 중인 모든 지점의 데이터 출력 
6단계: 시스템 종료

## 🟩 [2차 과제: V1.0] 입출력 + 리스트 + 조건문 - 향후 작성 예정
### **✨2차 과제 내용:**
기획 의도: 사용자로부터 수질 오염 물질인 BOD(생화학적 산소요구량) 농도를 직접 입력받아 제거 효율을 수학적으로 연산하고 정밀하게 진단하는 시스템을 구축하고자 했습니다.

관련 문법: 2주차 강의자에서 다룬 input() 함수를 활용한 데이터 입력, 변수(Variable)의 선언 및 명명 규칙, 그리고 정수(int), 실수(float), 문자열(str) 간의 자료형 변환(Type Conversion) 문법을 핵심 기반으로 삼았습니다.
    
### **🤖 AI 파트너십 과정**
User Prompt (내가 던진 질문)

"1차 때 기획한 변수를 바탕으로 코드를 짰는데 계산할 때 TypeError가 발생하면서 튕겨. 그리고 효율에 따라 S(우수)부터 F(불량)까지 등급을 나누고, 효율이 95% 이상이면서 유출수가 기준치 반 이하이면 '최첨단 친환경 공정'이라는 특별 인증 타이틀을 주는 조건문을 추가하고 싶어."

AI Response (AI의 해결 내용)

형변환 가이드: input()으로 입력받은 데이터는 기본적으로 문자열(str)로 인식되므로 산술 연산이 불가능하다는 원인을 진단하고, int()와 float()를 사용한 명시적 형변환 코드를 제공함.

다중 조건문 구성: if - elif - else 구조를 사용하여 95%/85%/75%/65% 기준으로 등급을 제어하고, and 논리 연산자를 결합하여 특별 인증 조건식을 완벽하게 결합해 줌.
    
### **🛠️ Troubleshooting & 기술 회고:**
(예시) 
1. **문제 1**: 사용자에게 유입수 BOD와 유출수 BOD를 입력받아 제거 효율 공식((유입 - 유출) / 유입)을 계산하려 했으나, 코드가 실행되지 않고 TypeError: unsupported operand type(s) for -: 'str' and 'str'라는 에러가 발생하며 강제 종료
    * **원인:**파이썬의 input() 함수는 사용자가 숫자를 입력하더라도 무조건 문자열(String) 자료형으로 받아들이기 때문임. 문자열끼리는 뺄셈이나 나눗셈 같은 산술 연산을 할 수 없어서 발생한 문제
    * **해결:** `int()`와 `float()` 함수를 사용하여 입력값을 숫자로 바꾸는 '형변환' 마법을 부려 해결함.
2. **문제 2**: 법적 방류 기준치를 입력받을 때 int(input())을 사용했더니, 사용자가 4.5나 5.5 같은 소수점이 포함된 정확한 기준치를 입력했을 때 ValueError: invalid literal for int() with base 10 에러가 발생
    * **원인:** 정수형(int)은 소수점을 포함할 수 없음. 방류 기준치는 오염도에 따라 0.5 단위의 미세한 실수 데이터가 들어올 수 있으므로 정수형 변환은 적합하지 않음
    * **해결:**소수점을 온전하게 보존하고 연산할 수 있도록 정수형 변환 대신 실수형 자료형인 float() 함수를 적용하여 형변환을 수행

### **🤖 AI 파트너십 과정**
 1. User Prompt (내가 던진 질문)

"2차 과제 코드는 한 번 실행하면 바로 끝나버려서 여러 지점의 데이터를 누적할 수가 없어. 프로그램이 종료를 누르기 전까지 무한히 돌도록 메뉴를 만들고 싶어. 그리고 기능을 입력, 계산, 출력 함수(def)로 쪼개고, 함수가 끝나도 데이터가 안 사라지게 전역 변수 리스트에 계속 누적하는 방법을 알려줘."

AI Response (AI의 해결 내용)
흐름 제어: while True 무한 루프와 사용자가 종료 번호를 선택했을 때 탈출하는 break 구문을 사용해 키오스크 형태의 메인 메뉴 제어권을 구축함.
변수 스코프 해결: 함수 내부에서 데이터를 추가하면 함수 종료 시 사라지는 지역 변수의 한계를 지적하고, 프로그램 최상단에 water_database 리스트를 만든 뒤 함수 내부에서 global 키워드를 사용하여 데이터를 영구 누적하는 이중 리스트(2D List) 구조를 완성해 줌.
    
### **🛠️ Troubleshooting & 기술 회고:**
  1. **문제 1:** ...2차 과제의 입력 로직을 def input_water_data(): 함수로 독립시켰더니, 메뉴에서 1번을 눌러 새로운 지점을 입력할 때마다 기존 데이터가 초기화 되거나 함수가 끝나면서 데이터가 사라지는 현상 발생.
     * **원인:** ...함수 내부에서 선언된 리스트는 지역변수로 취급되므로, 함수의 실행이 끝나면 메모리에서 자동으로 소멸하기 떄문.
     * **해결:** ..프로그램 최상단에 전역 금고 역할을 하는 전역 변수 리스트 (water_database = [])를 선언하고, 함수내부에서 global 키워드를 명시하여 전역 리스트에 .append() 데이터가 안전하게 누적되도록 수정.

 2. **문제 2:** ...전역리스트에 누적된 전체 지점 데이터를 출력하기 위해 for문을 돌렸을 때, 2차원 리스트 내부의 요소들을 인덱싱하는 과정에서 특정데이터의 위치를 찾지 못하거나 연산 과정에서 TypeError 및 출력 정렬이 꺠지는 오류.
     * **원인:** water_database는 1차원 리스트[지점명, 유입BOD, 유출BOD, 기준치] 들을 요소로 가지는 2차원 리스트인데, 이를 인덱스로 명확히 쪼개어 접근하지 않았기 떄문.
     * **해결:**성적표 미션의 정답 코드 구조 for student in grade_book:를 벤치마킹라여 반복문이 돌아갈 때 묶음 데어터 안에서 point[0], point[1]과 같이 인덱스 번호를 명확히 짖ㅇ하여 변수에 바인딩하는 구조로 해결.
   
 3. **문제 3:** ...수질 데이터를 입력받을 때 유입수 BOD농도를 실수로 0으로 입력하면, 제거효율을 계산할 때 ZeroDivisionError가 발생하며 프로그램이 강제 종료
     * **원인:** 효율 계산공식이 (유입-유출)/유입 *100 이기에 분모에 해당하는 유입수 BOD가 0이하일 경우 연산 오류 발생
     * **해결:**데이터를 입력받는 input_water_data() 함수 내부에 유효성 검사 조건문 if in_bod <= 0:을 추가하여 분모가 0이되는 상황을 차단하고 return 을 통해 함수를 조기 종료 시킴으로써 시스템 안정성을 확보

### **🛠️ Troubleshooting & 기술 회고:**
 1. [Issue 01] 비수치 데이터 입력 시 프로그램 Crash 현상
- **상황 및 원인**: 사용자가 수질 농도 및 기준치를 입력할 때 오타나 공백, 한글 문자열을 기입하는 순간 `int()` 및 `float()` 형변환 인터프리터가 `ValueError`를 내뿜으며 전체 프로세스가 즉시 다운됨.
- **해결 방안**: 입력 함수 영역 전체를 `try-except ValueError:` 블록으로 격리하여 잘못된 타입 유입 시 즉각 에러 팝업 텍스트를 제공하고, 프로그램의 생명주기를 파괴하지 않고 안전하게 상위 메뉴(`while True` 루프)로 탈출하도록 흐름을 방어함.

2. [Issue 02] OS 단 쓰기 권한 누락으로 인한 입출력 중단 리스크
- **상황 및 원인**: 관리자 권한이 없거나 다른 프로세스에서 파일에 독점 락(Lock)을 걸어두었을 경우, 또는 디스크 공간 부족 상태에서 `open()` 함수가 실행되면 시스템 크래시가 유발됨.
- **해결 방안**: 파일 저장 로직을 `try-except IOError:` 구문으로 밀봉하여 파일 시스템 예외가 감지되더라도 전체 흐름이 죽지 않고 유연하게 오류 현상을 로깅 및 예외 메시지만 반환하도록 조치함.
